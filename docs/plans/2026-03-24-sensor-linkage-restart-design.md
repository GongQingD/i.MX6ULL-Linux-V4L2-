# 多传感器联动重启设计文档

**日期：** 2026-03-24
**状态：** 已确认

---

## 目标

在当前稳定的 `My_Project` 基线之上，重新打开两条自动动作：

- `SR501 -> Camera_Project`
- `AP3216C -> LED`

本轮目标不是恢复历史上完整的线程化联动架构，而是先让“传感器变化能够驱动自动动作”重新稳定落地，并且便于板端验证和回退。

## 范围

- 修改 `My_Project` 中的联动状态变量和自动动作执行逻辑
- 保留当前 `SR501` 异步通知链路
- 保留当前 `AP3216C/DHT11` 的定时器读取链路
- 保留当前 `Camera_Project` 的启动方式和主链路
- 为当前阶段补齐可回读的中文文档和执行记录

## 约束

- 不恢复历史上整套 `SensorWorker/QThread + 自动/手动 ownership` 方案
- 不新增 UI 控件
- 不修改 `Camera_Project` 的主业务逻辑
- 不改内核驱动实现
- 所有结论都必须以当前仓库代码和本轮验证结果为准，不能把旧日志里的“曾经做到过”直接当作当前已交付状态

## 预期架构

- `SR501`：
  - 继续通过 `SIGIO + socketpair + QSocketNotifier` 把驱动异步通知转入 Qt 事件循环
  - 在通知处理函数中读取 `/dev/sr501`
  - 如果读到“有人”，则启动或续期自动相机会话
- `AP3216C`：
  - 继续通过当前 `QTimer` 每秒读取
  - 在同一条定时器链路中同时完成：
    - UI 数值刷新
    - `AP3216C -> LED` 自动控灯判断
    - 自动相机会话是否到期的检查
- `MainWindow`：
  - 保存少量联动状态变量，例如：
    - `cameraAutoRunning`
    - `cameraAutoDeadlineMs`
    - `lastSr501State`
    - `ledAutoState`
  - 执行动作仍然集中在主线程：
    - `QProcess` 启停 `Camera_Project`
    - `/dev/led` 写入 LED 状态

## 风险

- `SR501` 驱动读值可能存在“高电平保持时间长、回落慢”的现场特性，导致无人关闭时间看起来偏后
- `Camera_Project` 如果仍然处于板端运行中，部署时会出现目标文件无法覆盖的问题
- `LED` 当前同时存在手动按钮和自动控灯逻辑，若状态同步不清晰，可能出现自动重复写设备
- 若把过多历史逻辑一次性搬回，会重新引入此前难以收敛的交互类问题

## 成功标准

- `SR501` 检测到人时，`My_Project` 能自动启动 `Camera_Project`
- 无人持续 `5 秒` 后，自动拉起的 `Camera_Project` 能被正常关闭
- `AP3216C` 光照低于暗阈值时自动开灯，亮于亮阈值时自动关灯
- `My_Project` 主界面显示和手动按钮功能不被这次恢复动作破坏
- 本轮实现过程、阻塞和验证证据都记录到执行日志中

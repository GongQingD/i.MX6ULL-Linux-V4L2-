# Camera Interaction Priority Design

**目标**

- 在保持当前 `SR501 -> Camera_Project`、`AP3216C -> LED` 联动能力不退化的前提下，修正 `My_Project` 与 `Camera_Project` 之间的人机交互优先级。
- 明确 `My_Project` 是常驻核心页面，`Camera_Project` 是临时子页面；无论通过自动触发还是手动按钮进入相机页，最终都必须回到主界面。

**当前问题**

- 现有状态机只表达“有人/无人”和“相机是否运行”，没有表达“用户刚刚主动退出，想回主界面查看传感器数据”这一意图。
- 当前相机退出后，主界面会立即刷新并重新评估 `SR501`，若此时仍为 `1`，就会再次自动拉起相机，造成主界面停留失败。
- 当前“手动打开相机”属于 `Manual` 语义，不受“无人后 5 秒关闭”约束，这与“主界面永远是核心页”的新交互原则冲突。

**交互原则**

- `My_Project` 是唯一核心监看页面，负责稳定展示传感器数据和承接手动控制入口。
- `Camera_Project` 只是临时子页面，不拥有长期停留权。
- 自动联动不能覆盖用户刚刚明确表达的界面意图，尤其是“退出相机，回主界面看数据”。
- 后续交互设计优先解决“何时允许再次自动进入相机页”，而不是继续细分复杂 ownership。

## 方案对比

### 方案 A：退出后固定冷却时间

- 用户退出相机页后，固定忽略 `SR501` 自动打开若干秒。
- 优点：
  - 实现最简单
  - 对现有状态机侵入小
- 缺点：
  - 冷却时间内真实新人体事件也会被忽略
  - 不能区分“上一次感应残留高电平”和“下一次新触发”

### 方案 B：退出后等待 `SR501` 先回到 `0`，再允许下一次 `0->1` 自动打开

- 用户退出相机页后，进入“主界面优先”抑制态。
- 在抑制态期间，即使 `SR501` 保持为 `1`，也不重新打开相机。
- 只有当 `SR501` 先回到 `0`，说明本轮人体事件结束；之后下一次新的 `0->1` 才允许再次自动进入相机页。
- 优点：
  - 最贴合“手动退出是为了回主界面看数据”的真实意图
  - 可以规避 `SR501` 高电平保持期间的重复拉起
  - 语义清晰，便于和当前异步通知模型对齐
- 缺点：
  - 状态机会新增“退出抑制/重新布防”语义

### 方案 C：B 加最长抑制兜底

- 核心逻辑与 B 相同，但如果 `SR501` 长时间不回 `0`，则允许在一个最大抑制时间后重新自动布防。
- 优点：
  - 对异常长高电平场景更稳
- 缺点：
  - 比 B 多一层时间策略
  - 当前阶段未必需要

**结论**

- 当前推荐方案为 **B**。
- 原因：
  - 它能最直接表达“用户退出后，主界面优先”的交互意图。
  - 它不需要恢复旧版复杂的自动/手动 ownership 设计。
  - 它与现有“`SR501` 异步通知 + 主界面周期采样补充检查”的链路兼容性最好。

## 新交互语义

### 1. 自动进入相机页

- 当 `SR501` 检测到有人，且系统未处于“退出抑制”状态时，自动打开 `Camera_Project`。
- 只要持续检测到人，就续期自动关闭截止时间。
- 当无人并超过自动保持时间后，自动关闭相机并回到主界面。

### 2. 手动进入相机页

- 当用户在主界面点击按钮进入 `Camera_Project` 时，也视为进入一个“临时子页面会话”。
- 手动进入不再意味着“可以无限停留在相机页”。
- 手动进入后，如果 `SR501` 已无人，且用户在相机页一段时间内没有继续操作，也应自动回到主界面。
- 若用户之后没有继续停留理由，最终仍需回到主界面。

### 3. 手动退出相机页

- 无论这次相机会话最初是自动进入还是手动进入，只要用户在相机页主动点击“退出”，就立即回到主界面。
- 回到主界面后进入“退出抑制”状态。
- 抑制状态下：
  - 不允许 `SR501` 因当前残留高电平再次自动拉起相机
  - 主界面可以稳定显示传感器数据

### 4. 重新允许自动进入

- 抑制状态下，系统持续观察 `SR501`。
- 只有在 `SR501` 先回到 `0` 后，才解除抑制并重新布防。
- 之后下一次新的 `0->1` 才允许自动进入相机页。

## 建议状态变量

- `cameraPageVisible`
  - 当前是否处于相机子页面会话中
- `cameraReturnDeadlineMs`
  - 当前相机子页面自动回主界面的截止时间
- `cameraExitSuppressed`
  - 用户主动退出后，是否处于“主界面优先”抑制态
- `cameraExitSuppressionArmed`
  - 抑制态是否已经等到 `SR501=0`，允许重新接受下一次 `0->1`
- `lastMotionDetected`
  - 用于识别新的 `0->1` 边沿

## 建议状态转移

### 状态 S1：主界面空闲

- 条件：
  - 当前在 `My_Project`
  - 未处于相机退出抑制
- 转移：
  - `SR501` 新触发 -> 进入相机子页面
  - 主界面按钮点击 -> 进入相机子页面

### 状态 S2：相机子页面运行中

- 条件：
  - 当前在 `Camera_Project`
- 转移：
  - 用户主动点击退出 -> 返回主界面并进入退出抑制
  - 无人且超时 -> 返回主界面

### 状态 S3：主界面退出抑制

- 条件：
  - 当前在 `My_Project`
  - 上一次是用户主动从相机页退出
- 转移：
  - `SR501` 仍为 `1` -> 保持抑制
  - `SR501` 回到 `0` -> 解除抑制，进入主界面空闲

## 数据流调整建议

- `handleCameraFinished()` 不应在清空相机状态后立刻无条件允许自动重新拉起。
- 相机退出时需要区分：
  - 自动超时返回主界面
  - 用户主动退出返回主界面
- 对于“用户主动退出”，主界面恢复后应先设置退出抑制，再刷新 UI。
- `evaluateLinkage()` 后续应从“是否自动/手动 owner”转向“是否允许进入相机子页面、是否应返回主界面”的判断。

## 风险与边界

- 当前设计不要求新增线程。
- 当前设计不要求修改 `SR501` 驱动机制，仍保持异步通知。
- 当前设计不改变 `AP3216C -> LED` 已验证通过的联动逻辑。
- 当前设计已确认“无人体 + 无继续操作 -> 自动回主界面”的方向。
- 当前设计还未细化“哪些相机页操作会延长停留时间、延长多久”；这属于下一轮交互细化项。

## 实施建议

1. 先只改 `My_Project` 侧状态机与相机退出后的恢复逻辑，不改 `Camera_Project` 业务功能。
2. 先实现“用户退出后等待 `SR501` 回 0 再重新布防”。
3. 再统一“手动进入”和“自动进入”的返回语义，保证最终都能回主界面。
4. 最后再讨论是否需要把“相机页用户操作延长停留时间”做成单独策略。
